# Sigma 学习方法 — 严格执行手册

**这是学习的"宪法"，每次学习必须严格遵守，不得跳过任何步骤。**

---

## 核心原则

1. **不刷题 = 没学** — 每个概念必须做题验证
2. **不看代码 = R1/R2** — 复习时必须闭卷
3. **不重复题 = R3/R5** — 换题才有意义
4. **不讲明白 = 没懂** — R4 费曼讲解，讲不清的就是盲区

---

## 每个概念的完整学习流程（6 步，不可跳过）

### 步骤 1：诊断（首次接触）
- 问 3 个诊断问题，定位薄弱点
- 记录在 `session.md` 的 Diagnostic Summary

### 步骤 2：建立记忆锚
- 给一个画面锚（比喻）
- 画图或动画展示
- 用前端场景和生活场景强化

### 步骤 3：讲解概念
- 用问答式引导（不是直接给答案）
- 每讲一个点，问 1-2 个检验问题
- 用户答对了才继续下一步

### 步骤 4：手写代码
- 让用户自己写实现（不看参考）
- 写完后运行测试验证
- 写进 `practice/` 目录的对应文件

### 步骤 5：做必刷题（3 道）
- **必须做**，不能跳过
- 第 1 道：课堂上做，我引导
- 第 2 道：用户自己做，我检查
- 第 3 道：用户自己做，自己测试

### 步骤 6：记录进度
- 更新 `PROGRESS.md` 的完成状态
- 更新 `session.md` 的概念状态
- 更新 `REVIEW-CHECKLIST.md` 的复习时间
- commit 并 push 到 GitHub

---

## 间隔复习流程（5 轮）

| 轮次 | 时机 | 活动 | 通过标准 |
|------|------|------|---------|
| R1 | +1天 | 闭眼回忆画面锚，口述核心操作和复杂度（**不看任何代码**） | 能说出 3 个操作 + 复杂度 |
| R2 | +3天 | 不看代码手写 JS 实现 + 做第 1 道必刷题 | 代码能跑通 |
| R3 | +7天 | 做一道没做过的新题（**换题！**） | 能独立解出 |
| R4 | +14天 | 假装教别人讲原理+实现+场景 | 流畅讲完无卡壳 |
| R5 | +30天 | 做新题 + 30 秒说出思路 | 快速解题 = 掌握 |

**复习时问用户的问题：**
- R1："回忆一下这个概念的画面锚是什么？核心操作有哪些？时间复杂度？"
- R2："不看代码，手写一遍实现"
- R3："这道题你没做过，试试看"
- R4："假设我是小白，给我讲讲这个概念"
- R5："30 秒内说出这道题的思路"

---

## 文件组织规则

### 学习新概念时
1. 在 `practice/XX-concept/` 创建目录
2. 创建 `README.md`（学习指南）
3. 创建 `01-xxx.js`、`02-xxx.js`、`03-xxx.js`（3 道必刷题）
4. 每个 JS 文件包含：题目、方法讲解、代码模板、测试代码

### 复习时
1. 读 `REVIEW-CHECKLIST.md` 找到对应概念
2. 按 R1→R5 的流程执行
3. 记录复习结果

### 进度追踪
- `PROGRESS.md`：总体进度
- `session.md`：学习会话记录
- `REVIEW-CHECKLIST.md`：复习检查清单

---

## 禁止事项

1. ❌ 不做题就进入下一个概念
2. ❌ 直接给答案而不让用户思考
3. ❌ 跳过诊断直接讲解
4. ❌ 复习时让用户看代码
5. ❌ 重复做同一道题
