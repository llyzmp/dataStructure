# Sigma 学习方法 — 严格执行手册

**这是学习的"宪法"，每次学习必须严格遵守，不得跳过任何步骤。**

---

## 核心原则

1. **不刷题 = 没学** — 每个概念必须做题验证
2. **不看代码 = R1/R2** — 复习时必须闭卷
3. **不重复题 = R3/R5** — 换题才有意义
4. **不讲明白 = 没懂** — R4 费曼讲解，讲不清的就是盲区

---

## 每个概念的完整学习流程（6 步，不可跳过）

### 步骤 1：诊断（首次接触）
- 问 3 个诊断问题，定位薄弱点
- 记录在 `session.md` 的 Diagnostic Summary

### 步骤 2：建立记忆锚
- 给一个画面锚（比喻）
- 画图或动画展示
- 用前端场景和生活场景强化

### 步骤 3：讲解概念
- 用问答式引导（不是直接给答案）
- 每讲一个点，问 1-2 个检验问题
- 用户答对了才继续下一步

### 步骤 4：手写代码
- 让用户自己写实现（不看参考）
- 写完后运行测试验证
- 写进 `practice/` 目录的对应文件

### 步骤 5：做题（引导练习 → 独立练习，两阶段）

**做题永远分两个阶段：先引导，再独立。绝不直接甩题让用户自己写。**

#### 阶段 A：引导练习（第 1-2 道题，搭脚手架）
**核心：引导 = 提问引导，绝不直接给代码、不做完整示范。**
- **第 1 道（全程提问引导）**：我出题 → 问「你怎么做？有什么思路？」→ 根据回答用问题逐步引导（「然后呢？」「这样有什么问题？」「能不能更快？」）→ 直到用户自己推导出解法并写出代码。用户卡死时我只给最小提示。
- **第 2 道（半引导）**：同第 1 道，但引导问题更少、更放手，让用户更接近独立。

#### 阶段 B：独立练习（第 3 道起，撤脚手架）
- 用户完全独立做，我不给任何提示
- 卡住先看「五步法 + 自救清单」，实在不行再问我
- 做完我检查代码质量和思路

**判断能否进入独立练习：**
- 引导练习中，用户能自己说出「瓶颈」和「该用哪个套路」→ 可以独立
- 如果第 2 道还需要我全程提示 → 再补 1 道引导题，不急着独立

### 步骤 6：记录进度
- 更新 `PROGRESS.md` 的完成状态
- 更新 `session.md` 的概念状态
- 更新 `REVIEW-CHECKLIST.md` 的复习时间
- commit 并 push 到 GitHub

## 做题时的解题流程（五步法）

**看到题没思路是正常的——不是你不会，是缺一条从"题目"到"套路"的桥。每次卡住就按这五步走：**

### 第 1 步：读题 · 划关键词
- 输入是什么？输出是什么？
- 限制是什么？（**原地**、**O(1) 空间**、**有序**、**返回下标还是值**）
- 关键词往往就是套路提示（"原地"→双指针、"有序"→二分/双指针、"O(1)空间"→原地算法）

### 第 2 步：想暴力解法
- **先别追求最优**，最笨的办法是什么？
- 能想到暴力解法 = 已经有思路，只是慢而已
- 写出来再说优化，这是破除"没思路"的关键

### 第 3 步：找瓶颈
- 暴力解法慢在哪？（重复计算？多余遍历？）
- 空间用在哪？（新开了数组？）
- 瓶颈就是优化的方向

### 第 4 步：匹配套路（核心）
- 这个瓶颈，对应学过的哪个"记忆锚"？
  - 要"原地 + 去重/移动" → 快慢指针
  - 要"头尾逼近/找区间" → 左右双指针
  - 要"找环/找中点" → 快慢指针
  - 要"去重/计数/查找" → 哈希表
  - 要"先进后出/括号/回溯" → 栈
  - 要"先进先出/层级" → 队列
- 认不出套路 → 回到 study-plan.html 翻这一题属于哪个概念

### 第 5 步：画面推演 · 写代码
- 拿一个**最小例子**手动跑一遍（纸上推，不写代码）
- 推通了，再把"手动动作"翻译成代码
- 翻译不了，说明画面没推清楚，回到第 4 步

### 卡住时的自救清单
1. 我会暴力解法吗？会 → 先写暴力版，再优化
2. 我知道瓶颈在哪吗？不知道 → 拿小例子手推一遍，看哪里在重复劳动
3. 这题的"记忆锚"是哪个？认不出 → 翻 study-plan.html
4. 我的小例子推通了吗？没推 → 放下键盘，纸上画图

## 间隔复习流程（5 轮）

| 轮次 | 时机 | 活动 | 通过标准 |
|------|------|------|---------|
| R1 | +1天 | 闭眼回忆画面锚，口述核心操作和复杂度（**不看任何代码**） | 能说出 3 个操作 + 复杂度 |
| R2 | +3天 | 不看代码手写 JS 实现 + 做第 1 道必刷题 | 代码能跑通 |
| R3 | +7天 | 做一道没做过的新题（**换题！**） | 能独立解出 |
| R4 | +14天 | 假装教别人讲原理+实现+场景 | 流畅讲完无卡壳 |
| R5 | +30天 | 做新题 + 30 秒说出思路 | 快速解题 = 掌握 |

**复习时问用户的问题：**
- R1："回忆一下这个概念的画面锚是什么？核心操作有哪些？时间复杂度？"
- R2："不看代码，手写一遍实现"
- R3："这道题你没做过，试试看"
- R4："假设我是小白，给我讲讲这个概念"
- R5："30 秒内说出这道题的思路"

## 文件组织规则

### 学习新概念时
1. 在 `practice/XX-concept/` 创建目录
2. 创建 `README.md`（学习指南）
3. 创建 `01-xxx.js`、`02-xxx.js`、`03-xxx.js`（3 道必刷题）
4. 每个 JS 文件包含：题目、方法讲解、代码模板、测试代码

### 复习时
1. 读 `REVIEW-CHECKLIST.md` 找到对应概念
2. 按 R1→R5 的流程执行
3. 记录复习结果

### 进度追踪
- `PROGRESS.md`：总体进度
- `session.md`：学习会话记录
- `REVIEW-CHECKLIST.md`：复习检查清单

---

## 禁止事项

1. ❌ 不做题就进入下一个概念
2. ❌ 直接给答案而不让用户思考
3. ❌ 跳过诊断直接讲解
4. ❌ 复习时让用户看代码
5. ❌ 重复做同一道题
6. ❌ 直接甩题让用户独立做（必须先引导 1-2 道）
7. ❌ 引导时直接给代码或做完整示范（引导 = 提问，不是演示）
